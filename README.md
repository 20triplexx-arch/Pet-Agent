### 项目目标与已确认选择

- 项目名称为「宠伴」，面向准备养宠的新手和已有宠物的饲养者，完成“建档 → 问答与知识查询 → 计划预览与保存 → 提醒打卡 → 照护记录 → 根据新信息确认调整”的流程。
- 用户在比较开源项目并考虑成本后，选择 **FastAPI 官方全栈模板 0.12.0 + SQLite + Pydantic AI**。当前代码复用了部分认证和 UI 基础，其余业务为本项目实现，具体出处见 [UPSTREAM.md](UPSTREAM.md)。
- 本地 MVP 优先，首版完整支持猫和狗；其他物种目前仅支持档案与人工记录。鸟、龟、鱼等后续必须细分具体物种并补齐可靠资料。
- 默认是明确标注的演示模式，不要求模型密钥，不调用付费模型，不依赖云服务器、向量数据库或 Redis。真实模型通过独立适配层按需接入。
- 界面使用简体中文，覆盖手机和桌面。模型密钥在服务端配置；用户身份和工具数据范围由服务端登录上下文确定。

### 后续修改要保持的约束

1. 切换宠物时同步切换问答、计划、提醒和记录；其他用户的数据不能通过客户端参数或模型工具访问。
2. 知识与健康回答只引用实际检索的条目。资料不足要追问或说明，猫狗方法不能套用到其他物种。紧急风险在追问和模型调用前优先提示就医；健康回答不诊断、不自行开药或给剂量。
3. 计划先预览和编辑，明确保存后才写入。写入工具必须匹配用户明确指令与结构化载荷；工具失败不能报告成功。
4. 保留事务与幂等键：重试不重复创建，同键不同载荷返回冲突；宠物与用户权限由服务端校验。
5. 提醒采用 IANA 时区和当地日历，数据库保存 UTC，保留每个周期的完成历史。站内提醒不能描述为关闭应用后仍能收到的系统推送。
6. 延续本地低成本默认方案；新增模型服务、部署或物种支持时，以用户当前任务为准，并记录配置、资料和验证边界。

## 完整体验流程

1. 登录并在右上角选择宠物，或在档案页新增。未知项留空；生日优先于估计年龄，估计年龄记录估计日期并随时间推进。
2. 提问猫狗普通知识无需档案。选中宠物后，对话按用户和宠物分开保存；切换宠物会切换会话、计划、记录和待办。
3. 知识页按物种、通用照护/品种/食物/用品、已确认品种、阶段、主题或中文关键词筛选，查看真实来源与收藏。中文摘要未经兽医审核。进入“比较具体产品”，手动录入或本地OCR提取候选，核对后比较1—3件同类产品，明确保存才建立历史。食品需要另行确认才能加入营养资料，之后重新预览营养方案。
4. 在计划页设置可用时间，生成草稿，修改任务、时间、周期和依据，明确保存。保存会同步创建提醒。
5. 到期待办打卡，完成历史按每个周期单独保留。暂停/结束计划会暂停关联提醒。
6. 记录带日期的体重、饮食、活动、护理与异常观察。体重按发生时间取最新值并显示趋势。
7. 修改档案后重新生成草稿，或编辑原计划，确认更新。原任务的完成历史保留，原提醒暂停，不重复执行旧任务。

账户设置支持 IANA 时区。提醒保存 UTC，重复按创建时区的当地日历推进；账户时区改变仅改变显示，新提醒使用新时区。夏令时缺口中的新建时间会拒绝；模糊时间选择首次出现（fold=0）。重复任务遇缺口向后归一到有效时间。迟到打卡只标记当前显示周期，跳过的日期不伪造完成记录。未来任务不可提前打卡。

## 模型配置与成本

默认 `DEMO_MODE=true`，无密钥可用明确标注的演示模式。与质量基线分支整合后，显式设为false却缺少所选服务商密钥时，显示configuration_error，需模型的问答返回503；不会把真实模式冒充演示。演示模式采用真实检索、权限与本地工具路径和受控内容编排，不产生模型费用。

在根目录 .env 配置，重启后端：

```dotenv
DEMO_MODE=false
MODEL_PROVIDER=compatible
MODEL_API_KEY=服务商密钥
MODEL_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
MODEL_NAME=qwen3.7-flash
MODEL_MAX_REQUESTS=4
MODEL_MAX_OUTPUT_TOKENS=4096
MODEL_MAX_INPUT_TOKENS=32000
MODEL_CONTEXT_CHARS=48000
MODEL_TIMEOUT_SECONDS=90
MODEL_TURNS_PER_DAY=20
```

这是兼容 Chat Completions 的配置示例，模型名称和服务区域须以所选服务商实际可用项为准。独立适配层在 backend/app/model_adapter.py；Pydantic AI 的 OpenAIChatModel 使用服务端环境变量。任何密钥都不应放入 VITE_*、前端配置或提交到仓库。

SDK自动重试关闭；每轮最多4次模型请求、8次工具调用，32000输入token为整轮累计预算，4096输出token为单次上限，默认90秒整轮超时。上下文按48000字符预算选择历史和知识章节；最新问题、健康限制与专业建议不静默截断。默认每用户按上海日历每日最多20次真实问答尝试，失败也计数；设0可停止真实调用。设置页展示尝试数、失败数、已取得的供应商token，统计不是供应商余额或账单。未知失败用量不填虚假token，已取得用量即使回答被拒绝也保留。

真实模型现在负责综合品种、营养、产品及普通健康资料并追问，不再只输出页面入口；营养数值与产品预算仍由后端计算，医院事实仍通过独立授权查询。紧急提示和药物/诊断边界先在服务端处理。模型输出未完成、错误引用或不允许的确定诊断/新药物剂量会拒绝回答；这些保护是提示词和启发式校验，未经临床验证。当前未使用真实密钥做调用，兼容接口通过本地HTTP模拟验证；真实回答质量、延迟及成本需要配置可用模型后少量联调。具体预算与接口见 [深度问答说明](docs/DEEP_CHAT.md)。

## Agent 与工具权限

系统提示词：backend/app/agent_system.txt；十二个 Pydantic AI 工具：backend/app/agent.py；可审查 JSON Schema：backend/data/tool_definitions.json。在backend目录运行 `python -m scripts.export_tools` 可重新导出。最新增加 `get_breed_knowledge`、`assess_pet_products`：读取当前已确认品种或用户明确询问的对象，以及重新评估当前用户/宠物最近一次已保存比较。没有比较时返回录入入口，不编造产品数据。

服务端在模型调用与追问前识别紧急风险，并核对当前宠物档案和物种。紧急提示不调用模型，风险规则逐条关联资料 URL 与章节。药物/诊断问题采用受控就医准备提示，不给剂量；资料不足不让模型凭空回答。

工具 get_pet_profile、search_pet_knowledge 强制使用服务端上下文。save_care_plan、create_reminder、record_care_log 还需要明确写入授权及匹配的结构化载荷。模型不能设置 user_id/pet_id 或自己产生授权。模型自由问答只具备读取权限；明确保存草稿由服务端调度写入，人工保存/创建/记录接口调用同一工具实现。知识正文、档案与会话历史没有指令权限。

保存、记录、创建、打卡及聊天写入要求 Idempotency-Key。请求指纹包括操作和载荷；同键不同载荷返回 409。同用户同键重试返回已提交结果；业务记录与幂等记录在同一数据库事务提交，异常整体回滚。工具未提交或失败不会返回完成结果。引用从本次检索条目 ID 转换，未知引用导致回答拒绝并回滚；模型正文中的外部 URL 被移除。

对话支持完整明确指令，例如「记录体重 3.6kg」「记录饮食：食欲正常」「创建提醒：检查饮水；2026-10-10 08:00；每日」及对最新草稿说「保存计划」。当前记录使用本次时刻；历史记录请在记录页指定日期。不完整或模糊的指令会要求补充，不写入。聊天写入也先检查紧急风险；同草稿再次保存返回已保存结果。

## Agent 能力升级讨论（2026-10-10，实施前研究记录）

用户提出的方向是：根据宠物身体及健康特征定制营养方案；生病时快速查找附近可靠的宠物医院；扩展知识；支持更多具体物种。以下保留批准实施前的建议与当时差距；其中第一批已交付，当前状态以随后“第一批 Agent 升级”章节为准。

### 实施前的差距

源码核对：当前模型上下文主要包含档案、短对话历史和检索资料；五个工具没有读取照护日志、现有计划或完成历史的专用能力。计划采用受控通用任务，复杂意图及明确写入主要由规则处理。已有对话保存不等于可管理的长期偏好记忆。

档案缺少结构化体况评分、肌肉状况、食物能量密度、实际摄入及营养限制字段；当前没有营养计算模块、医院检索、位置授权、医院能力核验或文档识别。现有 16 条知识摘要无法承担广泛个性化营养与其他物种照护。个性化检索/规划仍有猫狗限制，不能只修改 species.json 就宣称其他物种已支持。

### 用户提出的四个方向

| 能力 | 应完成的实际任务 | 数据与边界 | 建议验收 |
| --- | --- | --- | --- |
| 个体营养管理 | 补齐关键资料，预览饮食方案、餐次与监测项目；确认后加入照护计划，根据新记录提出调整 | 具体物种、阶段、体重及趋势、体况评分与评估人/日期、必要的肌肉状况、绝育/活动、确诊病史与兽医要求、食物热量和现有摄入；区分热量估算与克数换算。首轮计算限资料充分的健康成年猫狗，疾病、妊娠/哺乳、幼龄、自制饮食等需要另行验证或专业方案 | 缺少食物热量不编造克数；每项数值可追溯到来源、计算规则与输入；用户更换食物后重新换算，保存前可编辑；模型与计算模块使用同一校验路径 |
| 附近医院与就医协助 | 用户授权定位或手输区域，按紧急程度、具体物种和接诊需求查找候选，展示地址、电话、距离和导航；整理就医资料 | 地图 POI 提供基础地点信息，医院官网、可核实资质及明确接诊资料用于补充；急诊、营业和特殊物种接诊均标明来源、核实时间与未知状态。地图评分与距离不能单独证明医疗质量 | 紧急提示先于追问；未授权定位可手输地点；第三方超时/无结果如实显示并可重试；未核实不声称正在营业、24 小时急诊或接诊该物种；无密钥不伪造附近医院 |
| 知识扩充与证据管理 | 覆盖营养、行为、环境、生命周期、健康观察、危险物品、就医与出行等实际问题，给出当前宠物适用的证据 | 按具体物种、阶段、主题及适用条件维护资料；机构来源、版本、摘要审核状态、更新日期、冲突与过时状态可查。公开可访问不等于可整篇复制或自动导入，使用原创短摘要及来源链接 | 不跨物种检索套用；引用对应实际条目；冲突或低置信检索说明不确定性；中文改写未经专业审核不标注兽医已审核；新增知识附代表性问题验收 |
| 具体物种与能力登记 | 从猫狗扩展至有可靠资料的兔、豚鼠、具体仓鼠，再按资料成熟度增加具体鸟、龟与鱼 | 登记具体物种及学名，每种分别声明建档/记录、知识、环境建议、营养规划、紧急风险等能力；房养、温湿度、光照、水质等字段按物种定义与校验，不给所有动物统一参数 | 支持一种能力不自动开放所有能力；未识别或未覆盖物种明确提示；猫狗方法不能作为其他动物的回退；新增物种需资料、专属规则、模板和跨物种测试 |

营养评估参考 [WSAVA 营养指南及工具](https://wsava.org/global-guidelines/global-nutrition-guidelines/)，其热量工具明确是健康成年猫狗的起始参考，体况与肌肉状况需分别考虑。照片可作为观察记录，不能仅凭单张图片确定体况、疾病或处方饮食。疾病营养以用户提供的专业建议为基础，系统协助执行与记录，不自动生成治疗食谱或补充剂剂量。

医院数据可接入 [高德地点搜索 2.0](https://developer.amap.com/api/webservice/guide/api-advanced/newpoisearch)；周边搜索需要坐标与服务端 Key，人工区域查询需地理编码或区域检索。实际方案应处理坐标系及授权，明确区分地图距离与路线耗时。医院专业能力必须额外核实；搜索结果只能展示有依据的匹配理由，不能输出无依据的「最好医院」排名。急诊场景鼓励及时电话核实接诊并就医，不通过长访谈等待完善档案。

多物种支持参考 [MSD Veterinary Manual：特殊宠物的福利与照护差异](https://www.msdvetmanual.com/special-subjects/animal-welfare/welfare-of-exotic-and-nontraditional-pets)。建议先扩展哪些具体物种是产品排序方案，尚无新增物种完成专业审核。

### 共用的 Agent 与交互基础

统一流程为「识别任务及紧急风险 → 读取当前宠物档案与有关记录 → 追问最关键的缺失数据 → 检索专业资料或外部服务 → 计算/校验并生成可审阅草稿 → 按明确指令写入 → 根据后续记录提出调整」。候选工具包括读取照护历史、读取现有计划、营养评估/换算、医院检索和生成就医摘要；工具仍需明确结构、服务端权限与可验证结果。数值与医院信息由可追溯数据和程序产生，模型负责解释、追问与组织内容。

界面继续维持低密度：首页保留今日照护与简短建议，营养、找医院、就医整理等通过对话和可展开的结果卡片完成，详细依据放在详情中。新增能力不等于新增大量首页卡片。主动检查首轮可在打开页面时触发；未打卡不能被解释为未照护，记录缺失不能被解释为健康异常。后续如实现后台检查或通知，需另行记录机制与范围。

## 第一批 Agent 升级（2026-10-10）

### 营养管理

从当前宠物档案的“营养资料与方案”或对话中的行动按钮进入 `/nutrition`。填写生命阶段、BCS、肌肉状况、日期/填写者、活动、健康及孕哺状态；核对带日期的体重，录入当前主粮、零食、包装热量和每日克数，确认零食及混合主粮分配比例。未知项可以留空，单独保存资料不创建任务。

点击“评估并预览方案”，返回可生成、待补资料或需专业评估。健康成年、BCS 4—5/9、肌肉正常且资料充分时，后端按 AAHA 2021 的 `70 × kg^0.75` 与活动/绝育系数计算起始范围，列出当前摄入、克数和真实来源。支持 kcal/kJ、每100g/每kg/每份；每份热量必须有份量克重，不猜杯、罐或勺的重量。混合主粮保持确认的热量比例，零食计入总量并限制确认目标不超过总热量10%。

明确选择每日目标、零食目标和餐次时间，保存前后端重新计算。方案包含每餐主粮/零食克数与管理性每周记录待办；可从计划页暂停、结束、打卡，修改食量需回营养页重新预览确认。新方案替换当前宠物旧营养方案，旧提醒暂停、历史保留，其他计划不受影响。新档案/记录/营养资料出现时只提示复评，不自动改量。旧预览、不同版本及并发冲突返回409；重试使用相同幂等键。

体况异常、肌肉损失、疾病、孕哺、成长/老年或高强度活动不自动制定增减重/治疗目标；档案含病史、过敏、兽医要求或新症状时采用保守处理，提供专业评估与非量化观察草稿。不能可靠给出数量时不显示虚假食量，紧急风险时禁止保存营养方案。用户自行确认成年阶段；已知未满12个月的猫狗会被拦截，不仅凭犬种/统一年龄认定成年。原有兽医建议保持用户原意，应用不修改处方。

### 医院与就医资料

从对话/紧急提示或营养页进入 `/hospitals`。点击后才申请浏览器定位，也可直接填城市、区县；选择5/10/20公里定位范围。WGS84坐标先经官方接口转换；每次最多10家。仅展示实际返回的名称、地址、电话、距离、地图导航与时间；区域搜索距离未知。营业时间是地图登记信息，急诊、资质及接诊物种都标“待核实”，不输出质量排名。周边候选按返回距离展示，供应商关键词检索返回顺序不代表医疗质量或全市最近医院。电话/导航均由用户点击。

无密钥、额度不足、无结果或超时均显示真实状态及高德搜索入口，不生成演示医院。位置不写数据库、日志或模型上下文；医院结果不建永久镜像。地图请求与聊天紧急提示分开，紧急就医提示先返回。

展开“准备就医资料”，补充症状开始、观察与已用药信息，读取当前宠物档案及最近30天最多100条真实记录，生成可编辑、复制、下载TXT的摘要。记录注明来源/日期，未知项明确标记；旧档案未记录每一项的修改日期，摘要不会把建档日期冒充观察日期。症状时间明确按此设备当地时间输入，摘要时间保存/显示ISO偏移。摘要不诊断，不自动联系、预约或发送医院；复制失败提供手动复制提示。摘要草稿不单独持久化，宠物切换即清空。

### 地图配置与成本

确认高德账号免费资格、Web服务Key与使用许可后，手动修改服务端 `.env` 并重启：

```dotenv
AMAP_ENABLED=true
AMAP_API_KEY=服务端Web服务Key
MAP_REQUESTS_PER_DAY=50
MAP_REQUESTS_PER_MONTH=500
```

应用按上海时区累计全应用请求（包含失败与坐标转换）；定位搜索通常消耗2次，区域搜索1次。每个HTTP请求8秒超时，无自动重试；超过日/月上限停止调用。设置页数字是应用请求数，**不是供应商剩余额度或账单**。免费条件以[高德账号方案](https://developer.amap.com/upgrade)为准，不承诺上线永久零费用。

**本批未进行真实地图联调或付费模型调用**，适配器以官方响应结构和HTTP模拟覆盖成功、无结果、失败与额度情况；真实密钥下的服务资格与实际接诊信息仍需核实。PostgreSQL仍只编译迁移SQL，没有数据库实机集成。
