# 宠伴资料入库、切分与检索规范

版本：方法 v1.1，2026-10-19（Asia/Shanghai）。

本文件规定以后新增、补深和更新资料时的工作方法，与[编辑模板](templates/knowledge-evidence.md)配套。2026-10-19已实现结构化证据块、构建检查和对应检索候选；实际验证、来源缺口和发布状态见[实施报告](EVIDENCE_REBUILD.md)，不能把规范或离线结果当作已上线能力或提速结论。

资料先按[分类规范](KNOWLEDGE_TAXONOMY.md)确定数据去向、物种、主分类、主题和适用标签，再进入下面的来源核对与切分。公共知识、用户私有记录、厂家事实和医院实时资料分别走自己的数据路径。

## 目标与现状

目标是让系统找到足够回答当前问题的完整依据，同时减少无关输入、重复检索和无依据扩写。资料切分、检索、上下文组装和回答验收必须一起设计。

实施前对五份 `backend/data/knowledge*.json` 的只读统计：95篇文章，正文长度中位505字符、最短365、最长992；按原 `##` 规则得到565个非空片段，片段长度中位94、最短38、最长187字符。片段统计包含标题；字符不是汉字数量，也不是模型token数量。补充后候选构建579个带依赖的完整章节块，95篇全文、579节及78个来源页已有助手编辑核对记录；保留短而完整的单元及未经兽医审核状态，详见实施报告。

实施前 `backend/app/knowledge.py` 先按整篇文章做BM25排序，再按标题切章和词语重叠取相关章节，`model_sections()`还会加入首节及标题命中适用、边界、风险等规则的章节。因此可能出现具体章节漏召回、结论和条件分离，或不相关边界一并进入上下文。新候选改用块BM25与独立依赖表；原路径保留用于对照与自定义文章兼容，公共浏览接口保持原语义。

现有短文也存在内容深度不足的问题。切分只能保留已有知识，不能补造来源没有支持的步骤、数值或专业判断。

## 一条资料的生命周期

```mermaid
flowchart LR
  A0[资料分流与分类] --> A[核对来源与适用范围]
  A --> B[编写完整主题文章]
  B --> C[提取完整证据块并关联条件]
  C --> D[离线索引和检查]
  D --> E[固定问题检索验收]
  E --> F[按版本发布与回滚]
  F --> G[问答失败归因]
  G --> B
```

每批资料应有编辑者、核对日期、变更说明和版本清单。来源核对、文字编辑和兽医审核是不同状态；没有专业审核仍标记 `editorial_summary_unreviewed`。

## 1. 先判断资料是否值得入库

1. 写清它解决什么用户问题，以及现有文章具体缺少什么。优先补深稳定文章ID，避免同主题短文重复堆叠。
2. 记录来源机构、具体页面URL、原文标题、发布日期或版本、访问核对日期、原文定位和适用地域；网页未标日期就留空，不能用收录日期代替。
3. 核对物种、阶段、对象和前提。品种标准资料不能独立支持健康结论；国外标签制度、法规或出行要求不能直接变成中国要求。
4. 对每项重要结论指出来源实际支持的范围。把专业来源结论、本项目原创操作建议、用户陈述和产品标签分别标记。
5. 无法核对、冲突未解决或不适用于当前能力范围的内容进入待核对区，不进入默认回答检索集。原文冲突应保留各方适用范围和版本，不能凭篇数或发布时间自动判定真伪。

原始资料只在许可范围内保留必要定位和核对摘录；不把版权文章整篇复制后再公开。编辑摘要保留原文条件，不添加机构背书。

## 2. 分成三个层次，分别承担阅读、检索和作答

| 层次 | 内容与用途 | 边界 |
| --- | --- | --- |
| 来源记录 | 原始页面身份、版本、定位、支持范围 | 证明依据在哪里；不是系统指令 |
| 主题文章 | 面向用户的完整指南，包含适用条件、操作、观察、边界及多来源 | 保留文章ID与收藏；不按检索块大小限制文章深度 |
| 证据块 | 能独立支持一个明确问题或操作的最小完整知识单元 | 可通过依赖关系补足必要条件；不是任意一句话 |

运行时再把相关证据块及必要依赖组合成一次性的“证据包”，并明确它支持哪个子问题。同一块只发送一次；一个块可以关联多个问题。证据包不是第四份独立维护的知识副本。

文章保持可读，索引属于可重建的派生数据。更新文章时不改既有文章ID、不破坏收藏；证据块通过稳定逻辑ID、修订号和正文哈希区分身份与内容变化，不使用每次全文重排都会变化的数组下标作为永久身份。

## 3. 按问题和完整语义切，长度只用于发现异常

切分顺序为：标题层级 → 一个明确主题或决策 → 完整段落、步骤或表格 → 必要时进一步拆分。

建议的首轮编辑范围为每块150—450字符；短定义完整即可，不凑字数。超过700字符时检查是否混合了多个问题；完整步骤确实不可再拆时可以例外。上述数值仅是待验证的项目起点，不是公认最佳参数，也不是当前导入器的硬限制。请求预算应使用实际模型对应的token计数；暂用字符计数时须明确其只是代理指标。

以下内容必须在同一块内，或通过必选依赖一起取回：

- 结论与改变结论的物种、生命阶段、健康状态、地域和日期条件。
- 数值、单位、上下限性质、计算输入及适用条件。
- 条件与例外、否定词、比较对象及因果限定。
- 有顺序的操作步骤、操作前提和会改变行动的停止条件。
- 表格行与表头、单位、脚注；跨页不能丢掉限定说明。

相邻段落不是天然依赖。不要因为位置相邻就把整篇或所有安全章节都加入每个问题。也不要只为减少长度切断完整的否定或条件句。

默认不做固定比例滑窗重叠。仅在连续长段确有跨界指代时保留必要的完整句或显式依赖；组装时按证据ID去重，避免同一句以多个块反复发送。标题路径和结构化适用范围随块保留。

## 4. 为每个块写清可回答与不可推导的范围

证据块编辑模板至少记录以下信息；它们是下一步派生索引的设计字段，尚不是现有 `ArticleImport` 接受的JSON字段：

| 字段组 | 必须表达的信息 |
| --- | --- |
| 身份 | `article_id`、`chunk_id`、修订号、正文哈希、标题路径 |
| 适用范围 | 具体物种、生命阶段、品种适用性质、地域、健康或用途前提；未知不可假定为全部适用 |
| 问题 | 可回答的问法、必要术语及经过核对的口语别名 |
| 内容角色 | 解释、操作、前提、观察、风险边界；必要时一块多个角色 |
| 证据 | 核对后的正文、来源引用ID、原文页码/标题/段落定位、支持范围及核对日期 |
| 依赖 | 必须一起读取的适用条件、定义、步骤或停止条件块；不得缺失或循环 |
| 推导边界 | 该块不能独立证明什么，是否涉及本地计算或专业评估 |

每块可补一行简短定位说明，例如“犬／独处适应／家庭练习／步骤与停止条件”。定位说明只从已核对的标题和元数据生成，不补造事实，不作为额外专业来源。

用户提出的问法、编辑生成的摘要和别名可以用于索引，但不能冒充来源正文。检索分数不能证明结论正确，引用了真实URL也不能证明该URL支持回答里的所有句子。

## 5. 不同内容采用不同切分方法

| 内容 | 推荐组织 | 特别保留 |
| --- | --- | --- |
| 品种 | 身份与个体差异、互动、毛发、健康观察等分别成块 | “倾向”与确定事实的区别；不能据品种直接定食量或诊断 |
| 日常操作 | 一个有完整顺序的操作单元 | 前提、实际步骤、观察和停止条件 |
| 食品与用品 | 一个选购判断或比较维度 | 适用对象、产品/配方身份、标签上下限及市场制度 |
| 营养 | 原理说明与后端规则分别管理 | 规则版本与来源；喂食数值仍由后端计算，不从零散文字推测 |
| 健康观察 | 可收集事实、就医准备、专业边界 | 紧急风险仍在模型与普通检索前执行；不依赖搜到某个块才提示 |
| 表格与对照 | 同一问题下保留表头和必要对照项 | 单位、脚注、空值和最小/最大性质 |

示例：“零食如何计入饮食”可形成一包：用途与适用范围 → 记录实际摄入的方法 → 与营养资料或专业限制的关系。不能只检索到“用于训练”就补造通用比例、克数或适配结论；用户只问零食定义时也无需塞入整套预算表。

## 6. 检索时先限定适用范围，再寻找具体依据

目标流程如下；2026-10-19已在候选代码实现，发布须通过独立验收：

1. 从本轮问题建立子问题和任务清单；只从历史补充相关指代、用户事实和重要限制，不把旧话题当新检索目标。紧急提示和用户权限检查维持原顺序。
2. 过滤物种与明确不适用的阶段、地域及品种限制。品种未知仍可使用通用照护；不能把档案的未知状态自动填为“健康成年”。
3. 以证据块而不是整篇作为主要排名单位。首版继续本地BM25及经核对的同义词，文章标题和块标题可参与检索；词语命中不是充分证据。
4. 每个子问题先保证至少一组直接相关依据，再加入会改变结论的条件与必要操作。资料不支持时标记缺口，不用弱相关内容填满名额。
5. 展开必选依赖，按块ID去重；保留不同来源的实质冲突。普通概念题不自动加入全部护理、选购和观察章节。
6. 以覆盖度、适用性、必要条件完整性和实际输入量选择最终证据包。不能简单截取全局Top-K，也不能为压缩输入而丢掉用户的并列问题。
7. 生成时只发所需正文和精简元数据，保留问题到证据的映射。每个事实结论引用实际出站依据；服务器据ID渲染可追溯来源。

可在试点比较每题召回8与16个候选、每题最终1—3个直接证据单元的配置。依赖块另计但必须进入输入预算；超预算时先去重复和弱相关内容，仍不足则说明范围并追问，不能截断关键条件。候选数也只是实验参数，不增加用户的模型或工具调用次数限制。

目前95篇的规模优先把本地检索和资料结构做好。向量检索或重排只有在固定题集证明现有召回不足、且质量收益值得新增延迟和维护成本时再接入。

## 7. 提速工作放在入库和本地组装阶段

- 切分、来源映射、别名核对和索引在资料变更时完成；不要每次提问重新切分全文或调用模型给每块写摘要。
- 派生结果按知识清单哈希、切分规则版本和检索配置版本缓存，修改后可靠失效。用户私有上下文须在权限过滤之后单独组装，不能使用跨用户共享的完整回答缓存。
- 检索缓存仅缓存公共知识候选，键包含问题规范形式、过滤范围和知识版本；不要把不同阶段或物种的结果错误复用。
- 现有单次模型请求路径、连接复用和分段展示继续保留。小输入可能降低处理量，但模型排队、生成长度和网络仍会影响实际速度，不能预先承诺百分比。
- 首段包含直接结论及必要条件，后面再展开操作。不能为抢先显示而把限定条件延后成容易误读的另一段。

## 8. 每次入库带问题，不只交付篇数

每篇新增或实质更新文章至少准备6种问题，允许一题覆盖多个类别：直接问题、口语改写、多条件适用、信息不足、相近主题干扰、否定/例外或跨物种边界。操作型文章另检查完整步骤及停止条件。

每题记录目标问题、宠物条件、必须召回的块及依赖、可接受答案要点、禁止结论、是否应追问和定位来源。人工逐项核对这些标注，不能由生成该文的模型同时自动给自己判满分。

试点建议先选换粮、独处、运输箱、清洁、食品标签5类，每类8题，共40题，猫狗和概念/操作/追问均覆盖；另冻结未用于调参的留出集。既有失败转为固定回归，不能删除。旧留出题用于修复后须改标为回归，再另设留出题。

先做零外部调用的导入、检索、依赖完整性和权限回归。只有确需验证生成质量时才在原预算、免费额度和资格机制内进行真实模型对比，不为本方法新增付费回退。

## 9. 质量与速度分开计量，固定同一构建再比较

| 维度 | 统计方法与发布要求 |
| --- | --- |
| 来源可追溯 | 发布块均有可核对来源与定位；原创操作建议明确标记，未审核不改审核状态 |
| 条件完整 | 固定题必需的条件/依赖到位率100%；计算“相关正文命中且必要条件同时进入上下文”的完整包召回率 |
| 检索质量 | 记录Recall@K、最终入选内容的相关率、子问题覆盖及无答案拒答；指标基于人工核对的标注 |
| 高风险边界 | 已知跨物种/阶段错误、数值单位丢失、严重概念错误和否定反转的固定回归零失败；不等于证明所有未知问题无风险 |
| 生成质量 | 逐结论/行动检查来源支持、覆盖、可操作性和简洁度；失败与误拦截单列，自动通过不等于医学准确率 |
| 成本与输入 | 记录候选/最终块数、去重数、实际输入输出tokens、模型请求数、保守等价费用；不把估算当账单 |
| 速度 | 分别记录本地检索/组装、首个合格段落、完整回答和真实浏览器等待的P50/P95；失败、冷请求和缓存命中分列 |

一次实验只改变切分或检索中的明确因素，先比较现状、带适用说明的原章节、完整证据块加依赖三种配置。模型、输入、数据版本、温度、输出策略、接口和测试顺序保持可比，同输入交错运行。冻结最终构建后修复代码要另记新构建，不能拼接旧结果宣称通过。

试点先要求完整包召回率不下降、高风险固定回归全过、最终输入量和检索耗时公开，再检查真实回答。后续完整30组真实对照继续沿用项目既有“至少20组改善且零退步”的目标，速度目标也单独验收；本规范不擅自放宽这些标准。

## 10. 发布、回滚与失败归因

发布清单包括文章版本、来源核对记录、切分规则版本、块及依赖哈希、检索配置、题集版本和测试结果。先在隔离数据中构建与验证，整批通过后发布；保留上一版知识和索引，迁移不得损坏用户收藏、档案或私有记录。

知识、检索或出站证据改变后，检查是否影响当前回答构建和模型资格；不能沿用不匹配的资格，也不能仅因文档已合并就切换本机运行版。

错误按来源不足、编辑失真、切分丢条件、召回失败、证据组装错配、历史干扰、生成扩写、校验误伤、计算/工具失败分别记录。先修产生错误的环节，而不是把所有失败都堆进系统提示词。

## 实施顺序与完成定义

1. 使用模板整理5个试点主题，先补足来源、具体内容和适用范围；冻结题集。
2. 增加可重建的证据块派生索引及依赖检查，兼容现有文章、收藏和来源接口。
3. 对比文章召回与块召回，再改证据包组装；先离线回归，再在允许预算内做生成对比。
4. 质量、速度、权限和资格均完成对应验收后，发布一批并持续记录失败，再扩大到其他文章。

上述步骤已有隔离候选及实际对照记录，发布验收另见实施报告。完成定义是有可重复的输入、产物、核对记录和对照结果，而不是“文章变多”或“平均块更短”。
