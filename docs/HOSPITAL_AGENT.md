# 医院综合查询 Agent（2026-10-14）

用户要求移除医院页的来源选择，让 Agent 结合高德和天地图。此版本取代上一批“手动单选、不双查”策略；两家独立的开关、服务端 Key 和请求上限保持。界面只有地点输入、定位授权和一个“查询医院”按钮。无新依赖、数据表、迁移或一级导航。

## 流程与事实边界

浏览器点击查询 → 登录及宠物权限校验 → 本地医院工具工作流检查两家配置与独立额度 → 并行查询可用来源 → 核对范围及重复登记 → 返回最多10家及每家资料来源 → 独立加载地图。

这个流程由 `backend/app/hospital_agent.py` 执行，不调用付费模型。Pydantic AI 对话工具 `search_nearby_hospitals` 提供综合查询行动入口；用户位置仍在医院页提供，不传给模型。模型不产生医院事实、星级或质量结论，紧急提示仍先于独立地图请求。

- 每家成功、无结果、失败、未调用都如实返回。单家失败或未配置时保留另一家候选；两家均无可用资料则提供手动地图入口，不产生模拟医院。8秒超时由各适配器执行，不自动重试；用户主动重试会再次计数。
- 只有规范化后完整名称相同、登记地区相同、且带数字门牌的完整地址相同，才合并两家重复条目。共同电话、连锁品牌、近似名称或只有路名都不足以合并。此规则保守，可能保留同一家医院的两条不同登记，避免误合并分院。
- 合并后保留各来源的原名称、地址、电话、营业时间及查询日期。空电话或营业时间可用另一来源补充并记录字段来源；不同值保留双方记录，显式提示冲突，不宣称已核实。
- 附近查询按适配器取得的距离排列；天地图距离是坐标直线估算，不是行车距离。行政区查询没有可靠距离时交替展示两家返回顺序，避免前一家占满十项。来源顺序和距离均不代表医疗质量或全区域最近医院。
- 行政区编码不一致时不混合不同地区，要求选择具体市区。附近查询两家各自匹配输入地点，响应保留每家的范围说明；匹配不可靠时该来源停止，不扩大范围。
- 天地图周边最多10公里；用户选择20公里时跳过天地图，保留高德的20公里。GCJ-02输入不交给天地图，也不把用户范围静默改小。浏览器定位的WGS84由两家各自按官方适配路径处理。
- 无可靠医院评分；营业时间为地图登记信息；急诊、资质和物种接诊均待核实。医疗质量未做电话或专业核验。

## 地图与隐私

静态小地图仍是高德服务端代理，只标注当前展示列表中实际取得高德坐标的候选。A—J对应列表位置，天地图独有条目没有字母标记；字母可能不连续。不能把天地图原生坐标直接放到高德GCJ-02图。

天地图独有条目的“按名称导航 / 查看地图”使用名称和登记地址打开高德搜索，用户核对具体机构。地图仅失败时仍保留候选及电话，支持手动重试。

两家 Key 只放服务端 `.env`。精确用户位置不保存到数据库、日志或模型上下文。医院响应当次处理；地图临时缓存只含公开医院位置及账户绑定令牌，10分钟过期，不建立永久POI镜像。内部 `_map_coordinates`、`_amap_point` 字段不返回浏览器。地图令牌仍校验登录及所属账户。

## 配置及成本

```dotenv
AMAP_ENABLED=true
AMAP_API_KEY=本机高德Web服务Key
MAP_REQUESTS_PER_DAY=50
MAP_REQUESTS_PER_MONTH=500
TIANDITU_ENABLED=true
TIANDITU_API_KEY=本机天地图服务端Key
TIANDITU_REQUESTS_PER_DAY=50
TIANDITU_REQUESTS_PER_MONTH=500
```

保存后重启FastAPI。未配置来源自动跳过，不需要在页面选择。旧 `HOSPITAL_MAP_PROVIDER` 保留兼容读取，但省略provider的搜索和医院页面不再按它单选。

上海日历独立原子限额包含失败请求，月额度不足时不误增日计数；不会购买或扩大供应商配额。选定地区的一次综合搜索通常各1次；手输地区或具体地点还需各自匹配请求。高德行政区候选及静态地图也消耗高德额度。应用计数不是供应商余额、免费额度承诺或账单。当前医院协调没有模型调用费用。

## API及工具合同

- `POST /api/v1/hospitals/search`：`provider` 可为 `auto/amap/tianditu/null`，省略或null按auto；明确amap/tianditu仅保留旧客户端/适配器诊断兼容。地点、半径和pet_id校验保持。
- 综合响应 `provider=auto`、`partial`、`provider_results`（各来源状态、候选数、消息、时间、范围）、`agent_summary`（local_rules、合并数、不同候选数、依据）。旧status/items/mode/queried_at/scope/map字段兼容。
- 每条增加 `sources`、`field_sources`、`conflicts`。来源记录及查询时间不是核验日期。`unique_candidates` 是两家本次最多各10条去重后的数量，不是全地区医院总数。
- `GET /api/v1/hospitals/usage` 省略provider返回合计计数并附两家独立providers；`?provider=amap/tianditu` 返回该家的顶层计数。合计余量不能代表任何一家仍有额度。
- `GET /api/v1/hospitals/regions` 与 `POST /api/v1/hospitals/map` 沿用高德及原权限、缓存、失败行为。
- 对话工具只返回页面入口、`strategy=combined_maps` 和使用说明；工具不接受模型生成的位置或用户身份，不自动电话联系、预约或保存搜索结果。

## 验证

新增20项隔离后端测试覆盖双查、保守去重、字段冲突、独立额度、超时、无密钥、20公里/坐标类型不兼容、地区不一致、最多十项、可见地图标记、跨用户拒绝和失败隐私。完整pytest275项通过。真实公开地区联调两家均成功：彭州行政区显示10家（各返回10）；公共政府地标1公里显示7家（高德4、天地图3），全部在范围内，地图HTTP200。本轮高德5次/天地图3次、模型0次，汇总见 [真实联调结果](hospital-combined-live-result.json)。

桌面/手机测试资料明确标为TEST FIXTURE，不是医院推荐。浏览器结果、构建、设计复核和数据库保护详见根目录 `TEST_RESULTS.md`。未做真实浏览器GPS、医院质量核验、行车距离合并或天地图站内地图接入。

官方适配合同沿用 [高德地点2.0](https://developer.amap.com/api/webservice/guide/api-advanced/newpoisearch)、[高德静态地图](https://developer.amap.com/api/webservice/guide/api/staticmaps) 和 [天地图地名搜索V2](https://lbs.tianditu.gov.cn/server/search2.html)。
