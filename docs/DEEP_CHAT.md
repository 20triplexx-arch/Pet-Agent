## 使用流程

1. 在AI对话选择当前宠物；没有档案也可询问明确的猫狗普通知识。
2. 提问支持最多12000字，显示字数，超限明确提示分次发送，正文不静默截断。
3. 需要时打开“补充资料”，填写目标、观察、时间线、饮食活动、环境变化、用户提供的专业建议及可选营养资料。发送时才作为本会话资料使用，带消息ID及时间来源。
4. 选择自动、简短或深入。自动对多问题、长输入或补充资料展开；简单问题简答。复杂问题篇幅700—1500字是表达参考，不是硬性字数保证。
5. 阅读结论、按需展开的分析/步骤/表格和来源章节。可复制回答；“继续深入”只填入追问，仍需用户发送。
6. 档案冲突会提示核对。营养数值在后端计算，量化仅适用于资料完整的健康成年猫狗；在营养页重新预览、确认目标并明确保存后才更改任务。

切换宠物、新建会话或切换历史会话清空未发送资料。同会话中的已发送非空资料沿用，并保留来源；空字符串不会删除以前的事实。需要完全清除会话背景时新建会话。资料不会自动更新Pet、PetNutritionProfile或CareLog。

营养补充面板支持单款主粮；混合主粮和零食在营养页完整录入。接口支持既有NutritionInput字段并逐字段校验。仅提供部分字段时沿用已保存资料；传入新foods数组是替换清单，旧清单的零食与分配确认不能继承，必须针对新清单重新确认。杯、勺、罐不猜克重；按份热量需要份量克重。用户填写“兽医”仍是用户报告，不等于应用核实了专业评估。

## 兼容接口

`POST /api/v1/chat`，登录Bearer身份及Idempotency-Key保持。旧客户端只发送text/pet_id等仍可用；新增字段可省略：

```json
{
  "pet_id": "当前用户的宠物ID",
  "conversation_id": null,
  "text": "猫昨天呕吐一次，精神和食欲正常。应该观察什么？另外换粮资料还需要核对哪些？",
  "answer_depth": "detailed",
  "context": {
    "goal": "整理观察，并判断是否继续换粮",
    "observations": "昨天一次，今天尚未出现；未自行用药",
    "timeline": "昨天晚饭后首次观察到",
    "diet_activity": "请在此填写实际食品、摄入与零食",
    "environment_changes": "请填写近期实际变化；未知可留空",
    "professional_advice": "请保留兽医原建议及日期；没有时留空"
  }
}
```

answer_depth为`auto | brief | detailed`，默认auto。补充资料最大字符数：goal/timeline/environment_changes各2000，observations/diet_activity/professional_advice各3000。nutrition可选，复用`backend/app/care_schemas.py`的NutritionInput；拒绝未知字段、错误枚举、负数与非有限数值。text上限12000，空白问题422。

2026-10-13聊天输入区改为模型选择，回答深度移到补充资料中。请求新增`model_id=default | demo | deepseek | compatible`，默认兼容旧客户端；每次请求独立选择已配置模型，返回`model_selection`与实际调用的`model_used`，没有调用模型则null。目录、配置和费用边界见 [聊天模型选择](CHAT_MODELS.md)。

原answer、mode、sources、draft、cards、message及conversation_id保持。新增可选字段：

| 字段 | 含义 |
| --- | --- |
| answer_depth | 实际采用的深度；auto解析后可能为standard/detailed |
| questions | 最多三个本次分析子问题 |
| context_conflicts | 补充与档案不同，等待核对的提示 |
| context_provenance | 每个沿用补充字段的用户消息ID及日期 |
| memory_sources | 更早用户消息的带来源摘录；不是已核实事实 |
| context_budget_notes | 为预算选择历史、记录或完整相关章节的提示 |
| complete | 完成结果为true；未完成返回错误，不保存半截回答 |
| sources[].sections | 当前知识文章的真实章节名，链接到详情页对应标题 |
| sources[].evidence | 2026-10-13新增：服务器提取的最多3段实际章节文字，每段最多400字符；可能为章节前部，完整内容可从章节链接核对 |

`GET /api/v1/usage/quota`返回当前用户的daily_limit、attempted_turns、failed_turns、remaining_turns、timezone、output_token_limit、note。既有`GET /usage`数组形状保持，设置页合并展示。身份取自服务端，客户端不能指定其他用户的配额。

## 分析与证据流程

紧急风险检查 → 读取当前授权档案 → 恢复本会话用户资料 → 最多三个子问题 → 按物种/品种/阶段检索 → 合并章节证据 → 读取营养、近期记录、执行中计划及需要的本地工具 → 回答已知部分并追问1—3项 → 返回可核对结果。

中文检索采用本地词典、中文二元词、同义词和BM25，最多三组每组四篇，交错合并最多九篇。具体品种指南与确定性工具的计算依据可另外加入。没有实时网络搜索；工具与知识正文不授予权限。显式问其他品种时标明目标，不使用当前宠物的数字替另一只宠物制定食量。

默认模型上下文读取最近24条消息；更早用户消息生成规则式摘录，优先健康限制、过敏、病史和专业要求，保留消息ID与日期。不额外调用模型摘要；单条过长摘录说明还有原文，合计约8000字符预算并记录遗漏数。最新问题、当前专业建议和档案限制完整保留。摘要有选择性，不能当作无限长期记忆或替代原会话。

营养、产品计算和真实近期记录由后端提供；真实模型负责综合证据、解释条件、行动步骤和追问。医院查询仍必须在独立页面授权定位或输入区域，问答不会编造医院、评分或已执行搜索。计划草稿使用现有受控规划器；“解释现有计划”不会偷偷生成新计划。模型自由问答不授权写入。

演示模式同样检索多个主题，呈现操作步骤、当前档案/用户资料和本地计算，持续标记“演示模式”。它仍是受控规则与资料编排，对任意复杂问题的推理和表达能力有限；不能把演示结果说成真实模型分析。

## 模型配置与成本

服务端根目录.env配置，重启后生效；不把密钥放入VITE变量。示例兼容Chat Completions地址与模型名沿用现有适配层，实际可用性由用户所选供应商决定。

| 设置 | 默认 | 含义 |
| --- | ---: | --- |
| DEMO_MODE | true | 默认无密钥演示；显式false缺所选服务商密钥时返回配置错误 |
| MODEL_MAX_REQUESTS | 4 | 单轮最多4次；兼容旧值5—6，实际仍限制为4 |
| MODEL_MAX_OUTPUT_TOKENS | 4096 | 单次输出上限；整轮最多该值×请求数 |
| MODEL_MAX_INPUT_TOKENS | 32000 | 整轮累计输入token预算，含工具往返 |
| MODEL_CONTEXT_CHARS | 48000 | 模型初始JSON上下文字符预算 |
| MODEL_TIMEOUT_SECONDS | 90 | 单轮整体超时；SDK自动重试关闭 |
| MODEL_TURNS_PER_DAY | 20 | 每用户上海日历日真实问答尝试数，0禁止真实调用 |

最多8次模型工具调用。超出字符预算先减少更早完整历史，以有来源摘要保留重点，再选择完整相关知识章节与近期记录；保护内容仍超预算则422要求分次，尚未调用模型。不删除最新问题或专业建议来强行发送。

2026-10-12与质量基线分支整合：支持MODEL_PROVIDER=deepseek、DEEPSEEK_API_KEY与DEEPSEEK_MODEL，或compatible的原配置，两者密钥不互借。显式选择真实模式却缺密钥时显示configuration_error，需要模型的请求503，默认DEMO_MODE=true仍可零密钥体验。执行追踪和累计评测预算保护保留；日常问答默认4096输出，固定评测账本上下文继续限制1800输出，不提高既有10元授权总额。旧真实基线属于合并前报告，尚未用真实服务商重新评测整合后的深度流程。

失败尝试也占每日次数，手动重试可能再次计费。取得的provider token会记录，包括返回内容被校验拒绝的情况；没有取得用量的失败只记录尝试，不虚构token。应用数不是供应商余额、免费额度或账单。

API失败/工具失败503、配额耗尽429、输出截断或引用无效502、参数错误422。输出finish_reason=length不保存半截回答；未知文章ID、不存在章节、明显确定诊断或新药物剂量拒绝输出。校验是提示词及启发式规则，未经过临床验证，不能保证发现所有不当回答。失败回滚会话业务事务，保留必要尝试/已知用量审计；已提交幂等键重放结果，不再调用模型，同键不同输入409。

30条质量问法见`backend/tests/test_deep_chat.py::QUALITY_CASES`，涵盖抓挠、新猫/幼犬到家、多猫、独处、刷牙、标签、换粮、拒食、航空箱、如厕、保暖、猫狗喂食、热量单位、预算、未知品牌、腹泻/呕吐观察、药物边界、摘要、缺营养资料、品种、多主题及三类紧急风险。检查实际条目ID/章节、问题相关要点与行动信息，另覆盖长输入、连续资料、冲突、历史来源、数值、失败、配额、旧客户端、用户隔离及幂等。
