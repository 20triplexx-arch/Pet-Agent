# 后续优化方案（2026-10-19）

现有提质成果已提交为 `b2518d6`，功能回归和CI通过，回答质量尚未达到20组改善、零退步。以下是待实施方案，本次仅整理方案并合并已有成果，不把方案当作已完成的优化。

| 方案 | 主要解决的问题 | 改动范围 | 建议顺序 |
|---|---|---|---|
| 问题—证据链重构 | 旧话题干扰、章节错配、动作和条件遗漏 | 上下文、检索、内部作答清单 | 优先 |
| 作答与校验重构 | 提示互相挤压、同义改述漏拦、否定误拦 | 生成约束、可判定规则、成对回归 | 与方案一配合 |
| 按阶段专项提速 | 首段偏慢、生成过长、输入冗余 | 模型输入、段落组织、性能测量 | 质量稳定后 |

## 方案一：问题—证据链重构

1. 在服务端建立本轮任务快照：所有明确子问题、并列任务、已知事实、来源日期、冲突和真正影响判断的缺口。
2. 将最新问题与相关追问作为检索输入；历史只补充明确指代和相关事实。过敏、病史及兽医限制继续保留，旧话题不能仅因词语命中进入本轮任务。
3. 每个章节明确支持哪个问题、哪项动作及哪些适用条件；文章命中不能代表全部问题已有依据。共用章节只发送一次。
4. 内部作答清单分别列出结论、条件、动作、停止条件、观察方式。只要求本题必要项，简单追问不重新填写整套清单。
5. 对缺口保留现有工具流程和重复读取收敛；本地任务整理不增加模型请求。

优先验证护理、独处、运输箱、清洁、换粮和多问题场景。先核对已有原始请求、出站章节及错误归因，再修改实现，避免将检索错误全部交给提示词补救。

## 方案二：作答与校验重构

1. 审查现有系统提示、来源规则和校验要求，合并重复或冲突的要求；将共同约束收口到统一的任务与证据结构。
2. 保留现有逐段JSON，要求各段明确问题编号和实际证据。结论所必需的条件与结论一起出现，由服务端生成引用。
3. 对数值、对象、已知字段、授权和明确逻辑关系采用可判定检查；按命题处理否定、条件和因果，避免仅检查整句是否含某个关键词。
4. 错误断言、正确改述、否定、双重否定、混合句及条件跨句成对验证。不能通过放宽健康边界或清除历史失败来提高通过率。
5. 段落检查与整篇检查保持一致；整篇失败仍撤回临时答案，不保存半截内容。不增加第二次模型纠错请求。

规则只能核对其确实能够判定的事实，不能替代语义来源审查。无法由程序证明的来源支持继续逐项复核；错误归因区分模型生成、检索不足和校验误伤。

## 方案三：按阶段专项提速

1. 使用现有上下文、检索、首token、首个合格段落、生成结束和提交计时定位耗时，补充真实浏览器等待测量。
2. 减少无关历史、重复资料和不必要输出。已实现的连接复用、知识缓存及一次请求路径继续保留，不重复当作新增成果。
3. 首段只承担直接结论及其必要条件；后续操作自然分段，不强制字数，不为抢首段展示而拆散条件。
4. 固定提示前缀后分别统计冷请求和实际缓存命中；没有命中数据就不宣称缓存提速。
5. 普通与深入回答分别统计，并报告失败、请求数、tokens及费用。速度改善不能抵消内容退步。

绝对目标继续为首段P50≤1.5秒、P95≤3秒，普通完整P50≤3秒、P95≤6秒；相对完整回答中位提速30%另行验证。

## 实施与验收顺序

- 建议先实施方案一及方案二中对应的校验修复，先把内容来源、对象和覆盖稳定，再实施方案三。
- 统一判定标准，保留原基线、全部失败和逐项依据。旧留出集如用于修复，应登记转为回归，并预先冻结新的独立留出集，不能继续称其未参与调参。
- 先完成隔离环境的离线回归，再冻结最终回答构建。真实测试开始后不修改该批的提示、检索或校验；需要修改时保留旧结果并将新构建另计。
- 同模型、同输入、同流式接口交错比较；至少20组改善、零退步，主要结论来源支持≥95%，已知严重原始错误不复现，失败单列。
- 继续使用原共享费用与免费额度账本，保留未知用量预留及本轮3元、累计10元上限。真实调用前重新核验免费余额、用完即停和预算；不足时只完成可独立验证的工作。
- 保持现有公共API、模型选择、一次请求路径及业务数据库结构。通过最终构建资格、质量和速度门槛后才部署；源码合并不等于运行验收通过。

已有实现、真实测量和未达项见[回答行动细节与来源复核](evaluations/QUALITY_COMPLETION.md)。
