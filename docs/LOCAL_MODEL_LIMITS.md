# 本地调用次数策略（2026-10-15）

> 同日后续升级保留本页的不限次数策略；本机默认改为阿里千问、输出上限4096，按回答深度分配1024/2048/4096。普通资料齐备的问答直接一次回答属于执行路径优化，不是重新限制调用次数。阿里真实评测独立遵守本轮3元/历史累计10元，详见 [阿里千问与回答优化](ALIBABA_CHAT.md)。

用户明确要求本地取消调用限制。当前根目录`.env`已设置`MODEL_LIMITS_ENABLED=false`，8000服务已重启加载。它取消三个应用次数上限：每日真实问答次数、每轮模型请求次数、每轮Agent工具调用次数。不是把数字调大；SDK的request_limit和tool_calls_limit实际传null。

## 配置与显示

```dotenv
MODEL_LIMITS_ENABLED=false
```

需要恢复历史限额时改为true并重启；此时每日MODEL_TURNS_PER_DAY生效，模型请求仍最多4次，工具最多8次。设置类默认true保持旧配置兼容，`.env.example`为本地体验示例明确false。仅本机这一策略项被改动，已有密钥、模型、地图和登录配置未改。

`GET /api/v1/usage/quota`继续要求当前用户登录，返回该用户的实际成功/失败尝试数。不限制时：

```json
{
  "limits_enabled": false,
  "daily_limit": null,
  "remaining_turns": null,
  "request_limit": null,
  "tool_calls_limit": null
}
```

null表示不限，0仍是有限额且没有剩余次数。设置页显示“本地不限次数”及真实用量，旧数字响应仍显示限额与剩余。刷新设置页即可加载新状态，服务端取消次数限制已即时生效。

## 流程与边界

本地不限模式不再以固定两轮模型或四次工具结束资料收集。不同参数的新查询可以继续；当当前请求中的只读工具出现相同名称及规范化参数的重复调用时，转入独立无工具JSON回答阶段，防止重复检索。写入仍先经过当前用户权限、明确授权及事务，重复检测不能让未授权写入变成成功。

用量、失败尝试、实际取得的tokens及幂等回放继续记录。取消的是调用次数，不是服务商计费、限流、模型上下文容量、每次输出量、整轮超时或来源/健康校验。专门执行的阶段评测仍遵守原累计10元独立预算与评测请求边界，本批没有付费模型调用，也没有重设预算账本。
