## 配置与启用

在项目根目录本机 `.env` 添加以下配置，不把密钥放入前端 `VITE_*`、源码、聊天或截图：

```dotenv
TIANDITU_ENABLED=true
TIANDITU_API_KEY=填入你的天地图服务端Key
TIANDITU_REQUESTS_PER_DAY=50
TIANDITU_REQUESTS_PER_MONTH=500
HOSPITAL_MAP_PROVIDER=amap
```

重启 FastAPI 服务，刷新医院页面。在“医院查询来源”选择“天地图”，再点击查询；未配置的来源标为“未配置”且不可选。`HOSPITAL_MAP_PROVIDER=tianditu` 可改默认来源，但不关闭高德。开关和 Key 都必须设置，否则不调用。Key 权限、实际接口配额和商用条件由开发者在天地图控制台核对；应用限额不是免费额度或供应商余额，不自动购买或扩容。

## 本批能力与边界

采用天地图[地名搜索 V2 官方接口](https://lbs.tianditu.gov.cn/server/search2.html)，固定 HTTPS `api.tianditu.gov.cn/v2/search`。指定省市区用行政区搜索 `queryType=12` 和九位国标码 `156+六位地区码`；具体地点先做地名匹配，再用周边搜索 `queryType=3`。手填市区没有地区码时先要求唯一行政区匹配；省级、歧义、错区、具体地点不匹配时停止，不回退全国或行政区中心。

周边搜索最多 10 公里，页面提供 1/3/5/10，后端也拒绝 20 公里；高德仍保留20。原生经纬度用于天地图周边请求，不接收GCJ-02，不套用高德转换结果。候选的坐标直线距离由后端计算和筛选，不是路线距离；没有坐标的条目不能假装附近。行政区查询严格核对返回省市县编码，距离未知保持空值。

只显示实际返回的名称、地址、电话、登记区域、分类及查询时间。来源信息来自该官方接口；评分、营业时间、急诊、资质、接诊能力不会猜测。原始文本和外部链接不是系统指令；网页不读取服务端 Key，Agent不替用户调用地图。

省市区及街道候选继续复用高德行政区接口，按高德限额计数；天地图 Key 本身不提供本批的区域树。高德未启用时仍可手填市区和地点。医院查询只使用当前选择的供应商，不自动双查或失败切换。地区候选与点击后的医院搜索属于不同请求，页面说明实际来源。

高德的站内静态小地图保留。本批天地图仅接搜索，尚未接其静态地图、瓦片或浏览器SDK；天地图结果以列表展示并说明范围，不画模拟地图。地图和导航按钮按名称、登记地址打开高德搜索，需要用户核对具体机构；不把天地图坐标直接画到高德GCJ-02地图。名称搜索不能保证两家资料完全一致。

## 接口与成本

- `POST /api/v1/hospitals/search` 增加可选 `provider: "amap" | "tianditu"`。不传时使用服务端默认。既有地区、地点、半径、宠物权限检查保持。
- `GET /api/v1/hospitals/usage` 返回默认来源计数、两个供应商的 `providers`、`region_enabled` 和 `region_provider_name`。可用 `?provider=tianditu` 读取该来源的顶层计数；不接收任意服务商URL。只返回启用状态，不返回Key。
- 天地图结果增加 `provider/provider_name/search_label/map_note`，无地图预览令牌；候选使用 `distance_kind=estimated` 和 `navigation_label=按名称导航`。旧客户端字段继续存在。

高德原 `MAP_REQUESTS_PER_DAY/MONTH` 不变。天地图按独立的 `TIANDITU_REQUESTS_PER_DAY/MONTH` 原子计数、上海日历，包含地点匹配和失败请求；月上限耗尽时不误增日计数。8秒超时、不自动重试，失败只提供手动重试和地图入口。零额度停止请求。

复用已有 `ExternalApiUsage` 的provider字段，无迁移或用户资料变动。没有增加地址、位置、POI、查询结果或密钥的数据库表/日志；天地图响应只当次处理，最大2MB。HTTPX完整外部URL日志被过滤，错误信息不回传Key、输入地址或供应商原文。

## 验证和待办

隔离测试覆盖国标码、错误地区过滤、重复条目、地点歧义、半径、经纬度、缺少字段、空结果、权限、无Key、失败/超时、独立并发限额和默认来源。桌面/手机覆盖来源切换、未配置不可选、手动重试、无双查、坐标估算/来源说明，以及原高德地图路径。完整结果见根目录 `TEST_RESULTS.md`。

首次配置保存并重启后，旧Key权限联调未通过。在公开彭州行政区进行1次应用查询和2次独立诊断，天地图返回HTTP403/301012，明确说明旧Key为浏览器端；使用真实服务端应用标识仍同样失败。三次都计入应用用量，没有高德故障回退或模型调用，没有私人位置或医院镜像。应用将该已知错误转为“请更换服务端Key（301012）”，只翻译已知枚举，不回显供应商原文、Key或地址。隔离测试新增两项真实HTTP403格式回归。

随后用户替换为服务端Key并按Ctrl+S保存，服务重启后地区查询权限通过。实际V2可将行政区呈现为POI，程序仅接受明确行政类别和匹配的省市区层级，拒绝同名错区及缺少父级的行政区猜测；地点在同地区有效坐标中优先唯一完整名称，其他办公区/停车场的近似名不当作同一地标，两条完整名称都匹配时仍停止。结构诊断后已补充回归，不通过时未扩大范围。

最终选定彭州和手填组合地区各返回10家候选，公共政府地标附近1公里3家，全部在范围内。全程12次真实请求，含旧Key和旧解析失败，未额外请求高德/模型或存医院镜像，完整pytest255项通过。未做真实浏览器GPS测试，医院资质和接诊仍需电话核对。对未来更换Key，仍须选“服务端”应用并保存重启；若需要站内交互地图，单独设计浏览器端Key与域名限制，不能把服务端Key交给网页。
