# 宠伴资料分类规范

版本：分类 v1，2026-10-19（Asia/Shanghai）。

分类先于切分。先确定资料属于什么数据、适用于谁、解决什么问题，再按[入库规范](KNOWLEDGE_INGESTION.md)建立证据块。本文件与[编辑模板](templates/knowledge-evidence.md)配套。2026-10-19已完成95篇显式分类与独立注释，具体处置、验证及未达项见[实施报告](EVIDENCE_REBUILD.md)；分类不等于专业审核，当前候选尚未通过发布验收。

## 1. 第一件事是确定数据去向

| 资料类型 | 保存与使用方向 | 可支持的范围 |
| --- | --- | --- |
| 公共专业资料 | 来源核对后形成公共知识文章与证据 | 仅支持原文实际覆盖的物种、对象、条件与结论 |
| 厂家资料与产品标签 | 产品事实、来源及具体配方/型号；涉及用户比较时按私有评估处理 | 支持标签声明、规格、厂家自述；不能单独证明疗效或独立质量评价 |
| 用户档案、观察、兽医建议 | 当前用户有权限的私有档案与记录 | 支持该用户报告的事实；未核实陈述不升级为确诊或公共规则 |
| 医院、营业信息与位置 | 外部服务查询路径，保留实际来源和查询时间 | 只表达真实返回结果，不转成永久公共知识或推定医疗质量 |
| 模型生成草稿、未核对网络材料 | 待核对区；核对后按实际资料性质归类 | 不能因生成流畅、带URL或分类置信度高就进入默认回答依据 |

分类不能授予访问权限。私有资料不进入共享索引，精确位置继续遵守当前不落数据库、不进模型上下文的策略。图片是输入格式，不是知识类别；包装识别仍按当次处理、用户核对和现有图片留存边界执行。

## 2. 用户浏览采用“物种 → 四类内容”

```text
宠伴知识
├─ 猫
│  ├─ 通用照护：养宠准备、到家适应、营养与体重、环境、互动、健康等
│  ├─ 品种：英短、布偶、缅因等；另标明家猫、混种等分类性质
│  ├─ 食物：主粮、零食、补充食品，以及标签、换粮、储存、成本等
│  └─ 用品：食水器具、砂盆、运输箱、玩具、梳洗、口腔、清洁等
└─ 狗
   ├─ 通用照护
   ├─ 品种：金毛、贵宾、柴犬等；另标明田园犬、混种等分类性质
   ├─ 食物
   └─ 用品
```

这是建议的浏览结构，不等于为每个分支复制一套文章。适用猫狗的资料保存一份并明确两种物种；每个品种入口组合专属指南和适用的通用资料。品种未知仍能读通用内容。

后续兔、豚鼠等沿用同样结构，但先完成独立能力登记；鸟、龟、鱼和需细分的仓鼠按实际物种建叶子分类。存在目录或资料标题不代表能力已开放。

四类内容兼容已有 `content_kind`：

| 主分类 | 现有值 | 如何决定 |
| --- | --- | --- |
| 通用照护 | `care` | 主要回答准备、日常照护、行为、个体营养管理或健康观察等问题 |
| 品种 | `breed` | 主要解释一个规范品种/分类的特点与专属照护，不按提到品种名称的次数判断 |
| 食物 | `food` | 主要解释食品类型、标签、选购、使用、换粮、储存与产品比较 |
| 用品 | `supplies` | 主要解释器具选择、尺寸、材料、维护、使用与替换条件 |

每篇一个主分类。涉及多个问题可加主题标签；确实包含多个独立完整指南时再拆成不同文章。不要因为喂养指南提到食盆就把它主要归为用品。

## 3. 主题和对象采用独立标签

| 维度 | 示例与规则 | 检索作用 |
| --- | --- | --- |
| 具体物种 | 猫、狗，后续明确到具体物种 | 防止物种方法串用；跨物种适用需有依据 |
| 品种适用性质 | 通用、指定品种、体型/毛发等特征相关 | 品种专属与通用资料可一起召回；外观描述不等于规范品种 |
| 主题与子主题 | 饮食与体重 → 体况观察；食物选购 → 标签阅读 | 明确解决什么问题；多问题查询不能只保留一个主题 |
| 生命阶段 | 成长、成年、老年及现有细分阶段 | 只有资料明确适用才赋值，年龄边界需有来源 |
| 生理与健康前提 | 绝育状态、孕哺、体况、疾病/饮食限制相关 | 表达知识的前提，不自动推断当前宠物具备该状态 |
| 生活与使用条件 | 室内、多宠、独处、运输、清洁等 | 提高相似问题中的匹配度 |
| 食品或用品类型 | 完整食品、零食、运输箱、牵引用品等 | 用于选购与比较，同品牌不同配方/型号分开 |
| 资料用途 | 解释、选购比较、操作、观察记录、就医准备 | 决定应优先召回概念还是操作证据；一篇可多种用途 |
| 地域与版本 | 中国大陆、其他具体市场、不涉及地域、待核对 | 法规、标签制度、出行要求及变更需核对，不能自动通用 |
| 来源与审核状态 | 专业指南、研究、品种标准、厂家声明、原创整理；分别记录核对与专业审核 | 控制来源能支持的结论，不以机构名自动替代逐结论核对 |

标签使用受控登记表，保存稳定ID、中文名、定义、父级与别名。每次新增标签先判断已有标签是否覆盖，避免“饮食/喂养/吃饭”成为三套同义分类。原始用户文字和原文术语仍保留。

“未知”“所有阶段适用”“不涉及该维度”是不同状态，不能将未填写自动视为全部适用。主分类空值的兼容默认值也不是专业适用性判断。

## 4. 现有主题先保持兼容

当前有11个主题文字值：养宠前准备、新宠到家、饮食与体重、居住与清洁、互动与训练、生命阶段、误区与危险、健康与就医、品种照护、食物选购、用品选购。

首批不重命名或覆盖这些 `topic` 值，以免破坏既有筛选、链接和回归。新增结构化主题登记时将旧文字映射到稳定ID，增加必要子主题；既有 `topic` 保留兼容。

“生命阶段”主题用于讨论成长或阶段转换本身；文章的生命阶段标签用于表达适用对象，两者不互相替代。

当前五份JSON在现有导入默认规则下为通用照护49、品种24、食物12、用品10。43篇旧资料未显式写 `content_kind`，由导入器默认 `care`；以后补标时逐篇核对，不能把默认值视为人工分类完成。本次仅记录现状，不改95篇正文或现有业务数据。

## 5. 分类的具体例子

| 资料 | 主分类与主题 | 独立标签和使用方式 |
| --- | --- | --- |
| 布偶猫照护指南 | 猫 → 品种；品种照护 | 指定规范品种；按原文分别核对各阶段适用性，相关食物通用知识通过关联展示 |
| 宠物食品标签阅读 | 猫/狗 → 食物；食物选购 → 标签阅读 | 食品类型、具体市场、比较用途；原文未覆盖另一物种或市场时不扩展 |
| 换粮时观察什么 | 相应物种 → 食物；饮食与体重 → 换粮 | 健康前提、操作/观察用途；不能由该分类推导统一天数 |
| 运输箱选购 | 相应物种 → 用品；用品选购 → 运输箱 | 选购/操作用途、尺寸和出行场景；法规或承运要求另标地域与日期 |
| 我家猫最近体重下降的记录 | 用户私有照护记录 | 用户ID、宠物ID、记录时间；与公共观察资料分别检索，不进公共知识分类 |

用户问“我家布偶猫适合这款幼猫粮吗”时，需要食品适用与标签证据、该宠物已知阶段/健康资料，以及确实相关的品种专属信息。不能只检索“布偶猫”目录，也不能仅凭“幼猫”标签认定适配。

## 6. 文章分类与切块标签如何衔接

1. 文章先确定数据去向、主分类、主题和适用范围，然后再切证据块。
2. 块保留文章身份和来源；自己的适用范围只可在有依据时细化，不因脱离原文而扩大。
3. 一篇“全阶段照护”里的成长章节可以只供成长问题使用；不把文章的宽范围机械赋给全部章节。
4. 文章分类与正文相冲突、块适用范围超出来源、必需标签未知时，进入待核对，不自动补为通用。
5. 已确认的物种和明确不适用条件属于资格过滤；主分类、主题与用途主要用于匹配和排序，跨主题问题不能被单一目录拦掉。未知事实要保留，不把缺失信息当作明确不适用。
6. 当前宠物默认提供检索上下文；用户明确询问其他物种/品种时建立本轮目标，不能继续套当前宠物。私人资料仍限定当前用户权限。

## 7. 每次新增资料的执行顺序

1. 分流到公共知识、厂家/标签事实、用户私有记录、外部实时服务或待核对区。
2. 选择具体物种、四类主分类和主要主题；登记不确定项。
3. 核对来源，补充阶段、特征、条件、地域、用途与证据性质等标签。可由模型提出候选，发布前由编辑核对，分类文本不能改变系统权限。
4. 填写适用与不适用范围，再编写完整文章、切证据块及绑定来源/依赖。
5. 检查错物种、错阶段、标签同义重复、不同市场混用、品种别名误判和未知被当作通用的回归题。
6. 隔离验证通过后按版本发布；保留旧ID、收藏、来源与可回滚的索引。

分类后能够更早过滤不适用内容，具有减少检索与输入浪费的可能；收益仍按入库规范中的固定题集、覆盖率和耗时实测，不预先宣称提速。

## 8. 落地边界

现有字段可承载 `species`、`content_kind`、`topic`、`breed_ids`、`life_stages`、`references` 和审核状态。多主题、用途、地域、特征条件、主题登记及块级适用范围属于下一步设计；在完成模型、导入校验和迁移前，不能直接添加到现有知识JSON，导入器会拒绝未知字段。

95篇批量重分类、独立注释和证据索引现已完成候选实现；检索与校验已在隔离环境验证，发布门槛及未达项见[实施报告](EVIDENCE_REBUILD.md)。现有知识ID、收藏及运行数据保留，候选尚未导入实际业务库。
