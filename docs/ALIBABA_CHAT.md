# 阿里千问接入与回答优化

> 以下保留上一阶段记录。逐段回答、免费池授权及当前验证以 [新说明](STREAMING_CHAT.md) 和 TEST_RESULTS.md 最新条目为准。

日期：2026-10-15（Asia/Shanghai）。本轮沿用现有账户、数据、登录签名和模型选择接口。

## 配置和模型选择

本机使用 `MODEL_PROVIDER=alibaba`、`DEMO_MODE=false`、`DASHSCOPE_MODEL=qwen3.7-flash`。密钥从后端进程的 `DASHSCOPE_API_KEY` 读取；不需要复制到 `.env`，不能放入 `VITE_*`。操作系统环境变量优先于根目录 `.env`。

地址顺序为：非空 `DASHSCOPE_BASE_URL` → `DASHSCOPE_WORKSPACE_ID` 对应的北京业务空间地址 → `https://dashscope.aliyuncs.com/compatible-mode/v1`。密钥与地址的地域必须匹配。当前凭证已用只读模型目录验证可见 `qwen3.7-flash`；目录验证本身没有发送推理请求。

`MODEL_PROVIDER` 和 `POST /api/v1/chat` 的 `model_id` 新增 `alibaba`。`GET /api/v1/chat/models` 增加“阿里千问 · qwen3.7-flash”，响应只含公开名称、服务商和可用状态，不返回地址、业务空间或密钥。原有 `default`、`demo`、`deepseek`、`compatible` 保留，旧请求及幂等指纹继续兼容。浏览器会话中用户明确保存的选择不被服务端默认覆盖；新会话采用服务端默认。

分发示例继续默认演示模式。阿里、DeepSeek 和通用兼容接口分别读取自己的凭证，没有借用密钥或自动切换服务商。鉴权、模型/地址不可用、供应商限流及超时分别提示；SDK和 Agent 均不自动重试。

使用已锁定依赖中的 `AlibabaProvider`。已安装的模型能力表早于 Qwen 3.7，因此显式声明其 JSON 输出和 `max_tokens` 能力。阿里请求传入 `enable_thinking=false`；无工具回答使用原生严格 JSON Schema，以防 JSON Object 模式中字段名漂移。DeepSeek保留原思考参数和兼容输出方式。

免费额度是服务商账户权益，模型目录的 `available=true` 只表示配置了密钥，不能证明余额或模型权限。本轮遇到 `AccessDenied.Unpurchased` 后停止调用；用户确认原模型额度耗尽并随后恢复额度，仍使用原 `qwen3.7-flash`，没有自动更换模型或启用按量付费。此错误单独提示核对资格、额度及权限；`AllocationQuota.FreeTierOnly` 单独提示免费额度用完即停。

如需改用其他赠送额度，在北京百炼控制台的“免费额度”页核对具体模型 Code、剩余 tokens、到期时间和“免费额度用完即停”，再明确修改服务端 `DASHSCOPE_MODEL` 并重启。不同模型及日期快照的额度独立；模型可调用不等于仍有免费额度。账户控制台设置不能由普通聊天 API 读取或保证，本项目不修改该开关。

## 回答流程和证据

服务端先处理紧急风险和明确写入，再收集当前宠物档案、会话补充、历史摘要、知识章节及适用的营养/产品等本地计算。每个子问题都有命中章节，且所需业务资料已经读取或明确缺失时，直接进行一次无工具的结构化回答。缺少用户测量或标签信息时保持未知并说明缺口，不要求模型再次读取同一档案。

仍需补充证据时进入 Agent。已经提供的档案、计划、近期记录及计算不再开放对应重复读取；聊天模型不接收写入工具或地点查询权限。同一请求中相同只读工具参数复用结果，不同查询可以继续。原有不限调用次数设置保留，只有输入/输出规模、整轮超时及专用评测预算继续约束；重复读取仍收敛到最终回答。

同一文章命中多个问题时合并各自章节。模型只接收一次完整匹配章节，并保留文章适用范围与安全边界，不同时重复发送全文。最新问题和专业建议不静默截断；上下文超预算仍返回明确错误。

补充工具仍保留原返回格式和服务端原文缓存；在实际出站请求中，将可信文章正文转换为本次查询的匹配章节和边界，与初始资料及本请求更早工具返回逐章去重。不同查询命中尚未给出的章节仍可补充。最终无工具阶段的业务工具结果也进行相同处理，避免品种等读取结果再次附带整篇正文。只有与服务端规范原文一致的实际发送章节进入证据登记，单有ID或标题不能成为可引用证据。

两条模型路径共用实际证据校验。文章 ID、章节标题、可选核对原文和正文内引用必须对应本轮实际提供给模型的内容，数据库里存在但未提供的章节不能通过。正文已引用实际提供的ID、但冗余citation_ids漏填时，服务端补齐来源卡；此步骤不补齐未知ID或未提供章节。仍拒绝不允许的确定诊断和新药物剂量；失败不保存聊天回答或伪报写入成功，已知消耗继续记账。

回答深度软目标：简短约100—200字、普通约200—450字、深入按需约600—1000字。深入回答覆盖结论、依据、适用条件、行动和观察复评方式；简单问题不凑字。请求输出上限分别为1024、2048、4096 tokens，并受服务端上限约束。本机上限从1800改为4096；旧DeepSeek专用评测仍最多1800。

真实来源对照发现过把护理时机的否定说明反写为禁忌、添加未支持的抓挠产品建议、遗漏零食比例限定等问题。对这些实际发现加入主题约束和有限的拒绝检查；不通过时不保存，也不自动付费修复。健康断言按分句及紧邻否定词检查，避免将“不一定是报复，不能排除疾病”误判成确定诊断；肯定诊断和新药物剂量继续拒绝。这些检查只覆盖已识别模式，不是完整语义判断或医学审核。

## 验证和费用边界

离线及浏览器测试显式清空外部凭证，使用独立数据库。执行日志只含请求ID、耗时、模型/工具次数、tokens、资料版本与错误类型；新增 `answer_path=direct|agent`，重复只读结果标注 `cached=true`。

真实比较脚本为 `python -m evals.alibaba_compare`。最小阿里接线后的源码保存在本机被忽略的 `artifacts/alibaba-baseline`，包含哈希清单；共享测量改动仅为阿里协议声明及预算计量。两版本在独立进程与数据库中使用同一模型、地域、固定数据集和4096总输出配置，逐场景交替 A/B、B/A 分发顺序。默认同时发出每对请求、等待两边完成后继续，最多两路；`--sequential` 可改为依次执行。报告标记实际分发方式、源码和基线哈希。阿里原生严格 JSON Schema 属于优化版本。合成响应与诊断保存在被忽略的私有目录，不写入日常执行日志。

对照选取既有100场景固定集的前60例，包含日常照护、缺失信息和多轮追问；本地规则直接回答的轮次单独计数。报告保留所有失败，同时提供两边都成功的配对统计，避免把快速失败算作提速。可用 `--only CB-001,CB-004` 定位固定场景；`--variant optimized` 仅验证当前版本，`--depth brief|detailed` 验证深度。诊断及重测同属本轮预算。

账本沿用 `backend/storage/evals/stage-one-budget.sqlite`。通过增量字段及 `runs` 表扩展服务商、模型、价格快照和本轮归属，既有费用及未决预留不清零。本轮ID固定为 `alibaba-quality-speed-20261015`，上限3元；历史累计上限继续10元。两项在同一 SQLite 写事务中检查，重启或重复运行脚本不会重置本轮额度。

请求前验证24小时内的阿里北京官方阶梯价格，以完整请求UTF-8字节及协议余量保守预留输入，使用相应阶梯和输出上限计费；已取得的用量按预留时价格结算。超时、传输失败或缺用量继续保留预留。估算不使用缓存优惠、不代表供应商账单或余额，也不改变普通聊天的不限次数设置。

实际通过数、费用、耗时和未达项见 [验收结果](../TEST_RESULTS.md) 与 [真实评测汇总](evaluations/alibaba-quality-speed.json)，20例发现与修订见 [助手来源对照](evaluations/ALIBABA_SOURCE_REVIEW.md)。自动行为检查和助手来源对照均不能替代真人或兽医审核。
